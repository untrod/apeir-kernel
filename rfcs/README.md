# RFC process

Use an RFC for changes to public contracts, state ownership, protocol framing,
durable formats, safety precedence, or kernel boundaries. An RFC states context,
decision, alternatives, compatibility, migration, security, and validation.

Accepted RFCs include the runtime object model, capability and Provider
contracts, model and Pack formats, the resource/capability graph, and the
independent Kernel distribution boundary.

Draft RFCs are discussed before implementation. Acceptance requires maintainer
approval. Small fixes and additive private implementation details do not need an
RFC.
